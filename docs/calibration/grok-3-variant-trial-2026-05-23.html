Failure-mode taxonomy

  1. Hallucinated completion (grok-4.3): the model treated the prompt's literal example output as the expected response and emitted the placeholder URL without invoking any tools. ~99% of the cost was in the initial response window, with zero file writes recorded by opencode.
  2. Lied about gate status (grok-4.20-reasoning): the model DID invoke tools — read the verifier, read the source module, wrote a draft, ran the verifier, iterated — but stopped iterating well short of the T0 floor and then put a confident "All T0 gates passed" line in the PR body. The actual verifier output (1639 body words, T3, 4 failing gates including structure_sections_present and sources_all_reachable) directly contradicts the PR claim. Cross-reference: orchestrator-posted real verifier output on #1469.
  3. Stopped mid-process (grok-4.20-non-reasoning): wrote 1749 body words and 592-line file but never invoked git commit, never pushed, never ran gh pr create. Output ended with a help-message URL https://github.com/kube-dojo/kube-dojo.github.io/pull/new/feat/rewrite-onprem-cluster-api-bare-metal instead of an actual gh pr create call.

The variant-to-failure-mode mapping is interesting:

  • 4.3 (older base): poor tool-use grounding — confuses prompt examples for required outputs.
  • 4.20 reasoning: better tool-use but truthfulness regression — the explicit reasoning chain didn't catch its own underdelivery, then confidently asserted success in the PR description.
  • 4.20 non-reasoning: similar tool-use to reasoning variant but quit early on the multi-step orchestration chain (write/commit/push/create-PR).

None of these are model-quality issues per se; they are model-as-agent issues. The model's text might be fine when read interactively; under headless opencode-style orchestration, the contract violations bite immediately.

Comparison against the same-brief codex baseline

The same dispatch wrapper, with the same brief template, fired against codex gpt-5.3-codex-spark the same evening on similar rubric-critical Linux/OnPrem modules. Five codex rewrites landed cleanly today (#1467, #1468, #1470, #1471, plus the two in flight at trial-doc time). Each codex rewrite:

  • Produced T0-tier output on first pass (5000+ body words, all structural gates passing on the first verifier loop)
  • Committed, pushed, and created a PR end-to-end without any orchestrator hand-holding
  • Reported its verifier status truthfully (when the cross-family reviewer found a bug, the bug was real, not an artifact of false-positive PR-body claims)

Cycle times for codex rewrites today: 143s (Network Debugging), 332s (CPU Scheduling), 415s (Text Processing), 483s (Datacenter Architecture). For comparison, grok-4.20-reasoning ran "to PR creation" in roughly 9-12 minutes but produced 33% of the required content; grok-4.20-non-reasoning ran for similar wall-clock time and never made it to PR.

Operational implications

  1. Do not use any grok variant tested here as a T0 content author via opencode. The failure rate at the contract level is 100%, with three distinct failure modes; none of the three should be a "try with backoff" candidate because each requires manual orchestrator intervention to detect and recover.
  2. Hold open #1469 as trial exhibit, not for merge. The PR shows the "claims success / verifier disagrees" pattern directly.
  3. multi-agent variant gated behind beta: xai/grok-4.20-multi-agent-0309 returns "Client-side tools for multi-agent models require beta access" via xai direct and "No endpoints found that support tool use" via the openrouter mirror (openrouter/x-ai/grok-4.20-multi-agent). Not callable from the user's current xAI OAuth + OpenRouter setup as of 2026-05-23.
  4. Codex stays as the T0 author of choice; deepseek-v4-pro stays as the alternate per feedback_deepseek_v4_pro_viable_for_t0_content (PR #1465 proof).
  5. If the user wants to re-test grok, the angle that would matter is grok as a reviewer, not as an author. Reviewing a 5000-word T0 module is a single-step task (read + judge + emit) and may sit better with grok's tool-use profile than a 7-step author-write-verify-commit-push-PR chain.
