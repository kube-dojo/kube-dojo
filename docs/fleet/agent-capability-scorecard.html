3. Fleet routing (differentiators — coding floor is uniformly high)

  • grok-build → sharpest final code-review gate.
  • glm → coherence audits + deep review. Local-only, never CI.
  • pool → free code + web-verify volume (browsing isn't unique; free is the edge).
  • deepseek → cheap all-rounder + best-value UK translator; browses when opencode-hosted. Ground-check its numbers.
  • cursor → high-throughput author/fixer/reviewer. Not a safe primary UK lane (russicism on longer text).
  • opus-4.8 → hardest reviews + top-quality UK (premium). gpt-5.5 → quality-critical author/review.

4. Ukrainian evaluation (for the translation project)

Graded objectively against VESUM (415K-lemma morphological dictionary — is the word real Ukrainian?) and a Russian-shadow morphology detector (russicism = confidence toward 1.0). Two tasks: native writing (~120-word explainer of a K8s namespace) and translation (~100-word technical paragraph with churn-heavy terms).

Native writing

All four wrote clean, fluent Ukrainian with no russicisms and native production terms (opus «робоча експлуатація», gpt-5.5 «виробництво», deepseek «промислове середовище», cursor «робоче навантаження»). Writing is uniformly strong; opus/gpt-5.5 slightly most polished. Writing is not the discriminator — translation is.

Verdict for the translation project

  • Quality ceiling: opus-4.8 — the translate-and-keep-English-in-parentheses pattern is exactly right for learning modules. Use for the highest-stakes / reference translations (premium lane).
  • Volume workhorse: deepseek-v4-pro — near-opus quality, cheap, no russicism → confirms the standing "prefer deepseek for UK." The default translation lane.
  • gpt-5.5 — usable; needs a post-pass to Ukrainize proper-noun terms it leaves in Latin.
  • cursor — NOT a safe primary UK lane. Passed the short paragraph earlier but produced a russicism on harder text. If used, it MUST clear the russicism gate (check_uk_changed.py).
  • pool — never for Ukrainian (bad); glm mediocre (anglicizes). Both are code models.
  • Every UK candidate still needs the russicism/calque gate — this test measured single short samples; long-module quality is not guaranteed by a short pass.

5. Methodology (reproducible)

  • Debug: a binary-search with a planted infinite-loop bug (lo = mid vs lo = mid + 1) → bug id + fix + triggering input.
  • Gen: longest_valid_parentheses (LeetCode-Hard) + 5 asserts; the output was executed.
  • Review: a snippet with 4 planted bugs (mutable default arg, MD5 for passwords, shell=True injection, div-by-zero) + a correct decoy (chunk) + an undefined-name latent bug.
  • Coherence: 4 docs describing one product with 3 planted cross-file contradictions (auth method, rate limit, format support).
  • Web-verify: "latest stable Astro version?" — true answer 7.0.6 (postdates training cutoffs); must browse to get it right.
  • Ukrainian: VESUM word-verification + Russian-shadow detection via the sources MCP.
