Agent & pipeline flow

sequenceDiagram
    participant Human as Human / Orchestrator
    participant API as Local API :8768
    participant Dispatch as dispatch_smart.py
    participant Agents as Claude / Codex / Gemini
    participant Pipe as pipeline_v2
    participant Content as src/content/docs/
    participant Gates as Quality checks
    participant Site as Astro build

    Human->>API: GET /api/briefing/session
    Human->>Dispatch: assign module task
    Dispatch->>Agents: write / review module
    Agents->>Content: edit markdown modules
    Pipe->>Agents: queue write/review/patch workers
    Pipe->>API: update module state + leases
    Gates->>Content: links, citations, health
    Content->>Site: npm run build
    Site->>Human: dist/ → GitHub Pages

Key directories

kubedojo/
├── src/                    # Astro site source
│   ├── content/docs/       # Curriculum (source of truth)
│   ├── components/         # UI (Footer, etc.)
│   └── pages/              # Custom routes
├── scripts/                # Python tooling (~100 scripts)
│   ├── local_api.py        # Session briefing, module state, pipeline API
│   ├── pipeline_v2/        # Queue + workers (write/review/patch)
│   ├── ai_agent_bridge/    # Multi-agent CLI bridge
│   ├── agent_runtime/      # Model adapters
│   └── checks/             # Site health, links, citations
├── docs/                   # Internal project docs (not published)
├── .pipeline/              # Runtime pipeline state (generated)
├── .bridge/                # Agent message DB (generated)
├── tests/                  # Python test suite
└── .github/workflows/      # Deploy + quality CI

Summary: KubeDojo is two systems in one repo — an Astro/Starlight static curriculum site (src/content/docs/) and a Python agent pipeline (scripts/, .pipeline/, local API on :8768) that writes, reviews, and quality-gates ~1,800+ pages before CI deploys to GitHub Pages.
