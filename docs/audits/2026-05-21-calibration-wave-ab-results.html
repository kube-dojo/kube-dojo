Wave A + Wave B calibration results

2026-05-21 · 80 cells (50 Wave A + 30 Wave B) · 8 models × 10 lanes · run_date=2026-05-21 · scoring judges: claude-sonnet-4-6 (× 2 for parity)

TL;DR. 80-cell sweep completed across 8 models (5 Wave A anchors + 3 Wave B production reviewers) × 10 lanes. The 9 lanes with at least one passable model produced clear quality bands. claude-opus-4-7 (anthropic), gpt-5.5 (openai), and claude-sonnet-4-6 (anthropic) are the top-tier triad — det rate ≥0.72 and LLM-judge avg ≥7.5 across prose lanes. gemini-3.5-flash-high collapsed (det 0.46, judge 1.67 — including one empty response on architecting and zero on orchestrating). qwen3.6-plus surprised on content-writing-long (det 1.0 + judge 8.0 — matching opus on the long-prose task) but stayed mid-tier elsewhere. deepseek-v4-flash held parity with deepseek-v4-pro on judge scores (7.75 vs 7.88) — strong cost-performance signal for the cheap-tier deepseek option. The orchestration lane that broke the pilot now flows real signal: claude-sonnet-4-6 leads with 1.0/8.0, opus + deepseek-v4-flash + gemini-3.1-pro-preview cluster behind at 0.75/7-8.

3. Surprising findings

gemini-3.5-flash-high collapsed in prose lanes. Judge avg 1.67 across 3 prose cells. One empty response (architecting), one all-zero-gates orchestration. This is sharply lower than every other model. Implication: agy/gemini-flash-high is not a viable substitute for opus/sonnet on prose work — it's fine for short structured outputs but breaks on architecture/orchestration. Re-validate any rule that promotes it as primary reviewer.
qwen3.6-plus ties opus on content-writing-long. qwen 1.0/8.0 vs opus 0.8/9.0 — qwen actually has higher deterministic pass rate (opus failed mermaid_block gate on this run). qwen judge avg 8.0 is one full point below opus 9.0 but well within usable range. Implication: Wave D's "cheap" tier (qwen3.6 base, gemini-3.1-flash-lite-preview, gpt-5.4-mini, claude-haiku-4-5) is worth running for content-writing-long — qwen3.6-plus already proves a non-anthropic non-openai model can match opus on long prose.
deepseek-v4-flash holds parity with deepseek-v4-pro on judge scores (7.75 vs 7.88). Per-cell judge scores are within ±1 across the same prose-lane fixtures. Implication: if cost-per-token matters and deepseek is in the cascade, prefer v4-flash. The v4-pro premium isn't visible in this 80-cell sample.
gemini-3.1-pro-preview has the highest deterministic pass rate (0.84) but a low judge avg (6.25). It's too structurally compliant, not pedagogically deep. That maps cleanly to its historical role on KubeDojo as a quick adversary reviewer (catches missing sections, mismatched anchors) but never as a content writer.
Sonnet beat opus on orchestrating (1.0 vs 0.75 on det). Sonnet's response mentioned the orchestration vocabulary more literally; opus's response was more abstract / strategic. Implication: for the orchestration lane the fixture's keyword set still drives the gate; the "prose-lane judge always runs" decoupling helps but the deterministic component is still keyword-sensitive. Section 5 for the gate-tuning context.

4. Lanes with NO differentiation

code-review: all 8 models scored 0.50. Either the fixture (`pr-1333-security-yaml`) hits the same partial-match pattern across all models, or `CodeReviewScorer.ground_truth_findings` is too coarse. Both `ground_truth_findings` and `no_hallucinations` are binary AND-of-alias-list checks; one fail collapses to 0.50. Fix in next sweep: add per-finding alias lists or score as ratio.
debugging: 7 of 8 models scored 1.00. Only gemini-3.5-flash-high failed. Fixture `resourcequota-pvc-mismatch` is too easy for differentiation. Fix: add a harder debugging fixture (e.g., race condition in informer cache, or kubelet eviction with skewed clock).

These two lanes contribute no signal to model ranking. Should be reworked before any Wave A re-run.

5. Methodology notes & data quality

Scoring pipeline

  • Stage A (deterministic gates): per-lane scorer in scripts/calibration/score_cell.py. Each lane has 2–4 gates. Pass rate = mean(gate_pass).
  • Stage B (LLM judge): runs only on prose lanes (orchestrating, refactoring, summarization, content-writing-long, architecting) per the PR #1370 decoupling. Two judges run; we used claude-sonnet-4-6 × 2 (instead of sonnet + gemini-3.5-flash-high) to avoid agy queue hangs in this run. Caveat: single-judge-family means no inter-family disagreement signal in this sweep.
  • Disagreement spot-check: if |judge1 − judge2| > 1.0, a human_spot_check row is written. With both judges being sonnet, this row is always 0.0 (no disagreement) in this sweep.

Data quality issues caught

  • 2 cells failed scoring:
    • architecting × gemini-3.5-flash-high — Wave A dispatch produced an empty response file. Judge failed with "Model response field is empty." The dispatch itself completed (recorded a 0-byte response). Likely a model refusal or context error.
    • orchestrating × gemini-3.5-flash-high — all 4 deterministic gates failed (cost_awareness, decision_card_discipline, routing_accuracy, same_family_serialized). The response existed but matched none of the synonym lists. Judge still ran (per PROSE_LANES decoupling) and returned 0.0.
  • SQLite lock contention — when score_cell ran with parallelism 3, ~70% of attempts hit `database is locked`. Fix applied: enabled WAL mode (PRAGMA journal_mode=WAL) + dropped to -P 1 serial. Re-scoring with WAL+serial succeeded on 67/67 attempts. Future Wave runs should enable WAL during ledger creation.
  • agy hung as a judge — dispatch_smart.py review --agent agy needs --worktree; the score_cell judge dispatch path doesn't pass one. agy timed out at 1800s per judge call. Workaround used: replaced gemini-3.5-flash-high judge with a second sonnet call. Action: patch scripts/calibration/run_cell.py:dispatch_prompt to thread a tmp worktree when the dispatched model uses agy-cli.

Cost (this run)

Per-cell cost_usd in the ledger is largely 0.0 — the dispatch wrappers do not yet record cost. The actual cost was approximately: 80 cells × 1 dispatch + 25 prose cells × 2 judges = 130 dispatches. Rough estimate: $0.50–$2.50 total (claude max OAuth + OpenAI Plus + agy free + deepseek/qwen via openrouter cheap).

6. Recommendations for next waves

  1. Replace the code-review and debugging fixtures — current ones produce no differentiation. New code-review fixture: a real PR with 6+ subtle findings (mix of correctness, security, performance). New debugging fixture: a non-obvious bug requiring multiple kubectl/log inspections to root-cause.
  2. Patch the agy-as-judge path in run_cell.py so the gemini-3.5-flash-high family judge runs. The current sweep lost inter-family signal because both judges were sonnet.
  3. Wave C (grok-4.3) + Wave D (cheap tier) can fire next using the same family-parallel scheduler. Estimated total: +60 cells, ~$3.
  4. Promote findings into role-allocation: for content-writing-long, qwen3.6-plus is a viable cheap substitute for opus when budget pressure justifies it. For fact-check, only gpt-5.5 is reliable. For orchestration, sonnet ≥ opus (consider sonnet as default orchestrator).
  5. Re-run gemini-3.5-flash-high with the architecting and orchestrating fixtures to see if the empty-response and all-fail-gates results were transient. If reproducible, this materially limits agy as a primary reviewer for those lanes.
