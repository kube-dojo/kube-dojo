Gotchas / learnings (new this session)

  • reset-stage slug = DASH-delimited key (on-premises-storage-module-4.X), NOT the slash path. The slash form FileNotFErrors on a nested .lock that doesn't exist. The per-module pipeline JSON lives flat at .pipeline/quality-pipeline/<dash-key>.json.
  • Board done = pipeline stage COMMITTED, NOT just an APPROVE review record. Writing the review file alone does not flip; you must reset-stage … COMMITTED (dash-slug). Review records are force-added to git (.pipeline/ is otherwise gitignored; 132 tracked).
  • Incident-dedup gate default mode is ABSOLUTE (fails on ANY violation, not just delta). 4.2's Ceph PG_DEGRADED/OSD-config Sources list false-matched the github-2021-mysql fingerprint. Suppress with <!-- incident-xref: github-2021-mysql --> within 200 chars of the match — slug MUST equal the check's internal slug (github-2021-mysql, defined in scripts/check_incident_reuse.py), NOT main's stale marker text github-august-2021-mysql.
  • cursor pads to exactly 5000 body_words (4.1, 7.9, 4.4 all landed at exactly 5000). De-fabbing during the fix-pass can dip it below floor → re-verify after every fix; the in-tree-plugin fix on 4.1 added enough words to offset the opener de-fab.
  • Background dispatch: do NOT combine the Bash run_in_background flag with a trailing & — the wrapper shell exits early and the completion notification fires on the wrapper, not the dispatch (the codex/cursor CLIs do survive, orphaned; poll the worktree commit instead). Use run_in_background alone for a real completion notification.
