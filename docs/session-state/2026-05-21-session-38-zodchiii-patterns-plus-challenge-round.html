3. The challenge-round pilot (highest-value finding)

Session 37 ran a 3-agent /code-review pass (reuse / quality / efficiency) on the calibration changes. I implemented 5 findings and deferred 3. Session 38 piloted the zodchiii "challenge round" pattern — spawn a 4th adversarial agent to challenge the original reviewers AND the orchestrator's deferral decisions.

Challenge agent found 2 real bugs the 3 primary reviewers missed:

  1. OrchestratingScorer empty-set inconsistency. Empty expected_routes set routing_ratio = 0.0, collapsing routing_accuracy to False for every model. Every other ratio scorer (CodeReview, McpUse, HarnessFollowing, Summarization) treats empty as vacuous pass = 1.0. Latent bug: fires on any future fixture shipping without routes. Fixed in 9715318d + regression test added.
  2. preflight_probe response validation. dispatch_prompt raises on empty response, but the probe didn't validate that the response was substantive. A model returning "I cannot help with that" would still pass preflight. Fixed in 9715318d — added response_text.strip() check + capture first 80 chars into the result dict for human inspection.

The challenge agent also pushed back on three of my deferral decisions:

  • Reuse #1 (FamilyParallelScheduler dead code) — DEFER UPHELD by orchestrator but flagged as "dead-code-with-paperwork." The challenge agent argued strongly for deletion. Not done this session — would be a separate clean-up PR.
  • Reuse #2 (recall-ratio helper) — challenge agent counted 6 callers, not 2 as orchestrator claimed. The "wait for third lane" trigger is already 6×. Not done this session (~30-min refactor, separate PR).
  • Quality #5 (DispatchOutcome dataclass) — challenge agent argued ~12 LOC for a type-checkable return shape. Not done this session.

Verdict: the challenge-round pattern is worth keeping. One pilot pass found two real bugs + raised three legitimate deferral pushbacks, for ~3 min of agent time. Recommend running it on every non-trivial PR going forward.
