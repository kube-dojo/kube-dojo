Operational lessons worth keeping

Worktree vs primary-tree test surface

After stash + worktree create, pytest from the primary tree tested the reverted primary state, falsely reporting "110 passed" when the worktree (with the new templates) actually had a broken test_report.py assertion. Agy ran tests in the worktree and caught it. Lesson: always run tests in the worktree where the actual changes live, not the primary tree. The cross-family reviewer doing exactly this caught the regression.

Hook fires on "Regression test:" body key without "fix:" title

The block-bugfix-merge-without-regression-test.sh hook treats ANY PR body with a Regression test: line as a bugfix that must add/modify the named test in the same PR. PR #1455 was data-only YAML; my "Regression test: tests/calibration/test_score_cell.py (existing tests cover...)" line tripped the hook because the path wasn't part of the PR's diff. Two workarounds applied: (a) retitle from fix: to chore:; (b) remove the "Regression test:" body key entirely for genuinely-data-only PRs. Already partially captured in feedback_bugfix_merge_hook_false_positive.md (session 39); this session reinforced the rule.

Codex flagged "pre-existing failure" that turned out to be cwd/worktree state

On PR #1453, codex reported a pre-existing test_quality_queue.py collection failure. Origin/main reproduced cleanly. The failure was worktree-cache state. Agy's later review re-ran tests cleanly. Pattern: when a writer agent flags a "pre-existing" failure, verify against origin/main in a fresh worktree before accepting the claim.

Agy review caught real bug + delivered design-quality feedback in one pass
