Process notes / lessons

  • Dead-link sweep is now a must-do on expand modules. Both waves had dead/wrong source URLs the verifier passed. A one-line grep -hoE 'https?://…' | curl loop catches them in seconds. Worth a CI guard or a verify_module enhancement.
  • API-version bumps need a CRD field-schema diff (Kueue cohort→cohortName). Don't sed apiVersion strings blindly.
  • opus-inline R2 economics: for cursor/codex-authored expands, reading via git show HEAD:path (stdout, no worktree CLAUDE.md re-injection) lets opus review without the ~50–150× subagent token cost. Used for 1.4.
  • deepseek review-harness flakiness: the 1.4 deepseek review landed in a browser-only harness with NO file access (couldn't read the worktree path) and bailed asking for the file — re-routed to opus-inline. deepseek's 1.1 review worked fine (found the real dead links). Inconsistent; prefer cursor/codex/opus for reviews when the verdict is load-bearing.
  • Reviewers read worktree files by absolute path (read-only, cwd=PRIMARY, TARGET=.worktrees/… abs path) — no need to push the branch first.
  • Both waves: frontmatter byte-identical to main except revision_pending:false → Zod-safe; confirmed before push. fences/details balance checked.
