2. #1577 commit-subject convention (the "fix #N" auto-close bug, twice)

Issue #1577 (the Class A epic, 12 modules) was auto-closed by GitHub twice this session despite every PR body using Refs #1577 (not Closes). Root cause: every commit subject started with chore(content): fix #1577 module X..., and GitHub's auto-closer regex matches the fix #N pattern in the commit message, not just the PR body. PR body Refs does not override.

Reopened twice; closed for the second time when PR #1584's rebase-merge brought the original "fix #1577" commit subject onto main. Final reopen comment is on the issue. Going forward, every #1577 dispatch brief must instruct: commit subjects use phrasing without close-keywords, e.g. chore(content): #1577 module X-Y — N defects fixed or module X-Y refresh per #1577. Locked as feedback_commit_subject_avoid_fix_n_pattern memory.
