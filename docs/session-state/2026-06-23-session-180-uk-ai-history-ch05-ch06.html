Headroom proxy — two failure modes diagnosed (NOT the repo)

The interactive session routes through the Headroom proxy (ANTHROPIC_BASE_URL=127.0.0.1:8787). It does synchronous pre-upstream context compression (stats: run_seconds_max=45.1s > its own compression_timeout=30s, concurrency=3). Two consequences:

  1. Stream-idle timeouts on large single generations: the proxy holds the request while compressing (no tokens stream) → client's idle timer fires → Stream idle timeout - partial response received. Mitigation used: write files in small chunks (worked — zero timeouts on ch-06's 6 chunks).
  2. Lossy Reads: large Read tool outputs come back with [N items compressed … hash=…] markers that silently drop source content. Translating ch-06 from such a Read produced a summarized translation — caught only by cross-family review. Fix: read faithfulness-critical sources in <40-line chunks (uncompressed); verify completeness with char-ratio ≥97% AND paragraph parity AND no per-paragraph outlier. New memory: feedback_never_translate_from_compressed_read.
