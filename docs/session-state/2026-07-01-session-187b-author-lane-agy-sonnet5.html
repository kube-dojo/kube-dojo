2. Headroom is NOT the agy culprit

The Headroom proxy is healthy (v0.28.0) but Anthropic-only (upstream: api.anthropic.com, gemini_api_url: null). agy is a Gemini model → its traffic never touches the proxy. The s182 timeout was --print-timeout 5m (fixed); the s183/today "no file" is agy-harness, not Headroom. (Session env has ANTHROPIC_BASE_URL UNSET anyway — routing off since s181.) The separate Headroom concern — lossy compressed Reads + stream-idle timeouts on one big Write — hits the opus translation path, and that's what the chunking question is really about.

3. Sonnet 5 -p as an author lane

Model facts (claude-api ref): claude-sonnet-5, adaptive thinking only (budget_tokens 400s), effort low→max, default high, xhigh = coding/agentic sweet spot, new tokenizer ≈ +30% tokens, $3/$15 per 1M ($2/$10 intro through 2026-08-31), 1M ctx / 128K out.

⚠ CORRECTION (user, s187b): claude -p is CANCELLED / OFF — do NOT use it. So a Sonnet-5 author lane via the Claude CLI (claude -p --model claude-sonnet-5 --effort high) is off the table, even though the flag (--effort <level>, works with --print) exists. This supersedes the s155 "claude -p usable again" note.

Consequence: using Sonnet 5 as an author would require a raw Anthropic-API adapter (SDK call with model=claude-sonnet-5, output_config.effort="high") — new infra, and it bills API pay-per-token ($2/$10 intro, +~30% new tokenizer), not the subscription. That's a bigger lift + a real-$ decision. PARKED until the user decides it's worth building/paying for. If pursued: high effort is right for translation (intelligence-sensitive, not agentic). For now the author A/B uses the fleet that works via existing transports (deepseek / agy-if-fixed / codex), not Sonnet 5.

4. Chunking (chapter/section-by-section) — keep per-file granularity

A robustness/reviewability win, not a correctness requirement. The Headroom long-output failure only bites Headroom-on (currently off). The proven mitigation (s180) is chunked I/O within a module (<40-line reads, chunked writes) — no need to split into separate sessions. Per-file (≈ chapter/section) is already the right unit: cleaner review, PR boundaries, timeout margin, parallelism. The bigger efficiency lever is a stronger author, not the chunk size.
