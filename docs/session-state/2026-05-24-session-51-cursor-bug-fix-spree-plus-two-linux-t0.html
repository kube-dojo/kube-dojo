PR #1487 — cursor discuss adapter monitor_state argv parsing (issue #1488)

Bug: ab discuss firing to cursor-agent always failed with error: unknown option '--- monitor: project state (volatile) --- ...'. Root cause: _channels.py:466 prefixes the monitor-state JSON section with the literal token --- monitor: project state (volatile) ---, then _cursor.py:_build_command passes the prompt as final argv to cursor-agent. Commander.js (cursor-agent's parser) treats any argv element beginning with -- as an option flag even after positional args have started.

Fix: insert POSIX -- end-of-options marker before the prompt argv. One-line semantic change in _cursor.py:_build_command + 1 unit test asserting marker placement on a representative monitor-style prompt. 38 seconds from dispatch to committed.

Codex R1 review: APPROVE no findings — verified -- placement after all options, test would fail without fix, sibling adapters (Hermes/Qwen/DeepSeek/Agy/Codex/Claude/Gemini/OpenCode) unaffected (they use stdin or --prompt option, not trailing positional argv).

Operational lessons (new this session)

1. Codex auto-rebase in --mode danger --worktree X can overwrite fix-pass HEAD

While the codex R2 review on PR #1494 was running in .worktrees/linux-6.4-netdebug, the worktree's HEAD got rebased from de99edff (the fix-pass commit) to 52e5eb7b (a different branch's merge commit). Codex's stderr noted: Codex danger-mode dispatch left origin stale: branch=feat/linux-6.4-network-debug-t0 local=52e5eb7b2410 remote=de99edff3f35. Origin retained de99edff (correct), only local rebased. Recovery: git reset --hard origin/feat/linux-6.4-network-debug-t0. Save as memory: feedback_codex_danger_rebase_worktree.md — pin worktree to origin ref before applying inline edits.

2. git reset --hard <ref> updates the current branch ref AND can move primary onto a worktree branch

I ran git reset --hard origin/feat/linux-6.4-network-debug-t0 from the primary repo while accidentally still cd'd into the linux-6.4 worktree. That moved the worktree's branch correctly; but at a different point I ran a similar reset from primary while on main and primary got switched to feat/linux-6.4-network-debug-t0 as the current branch. Required git checkout main && git reset --hard origin/main recovery. Lesson: always pwd + git branch --show-current before destructive ref operations.
