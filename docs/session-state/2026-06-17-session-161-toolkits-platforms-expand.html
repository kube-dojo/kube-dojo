PR hygiene — Dependabot #2011 + the marker bug (#2015)

  • #2011 (js-yaml 4.1.1→4.2.0, a transitive dep) tripped the supply-chain lockfile-integrity tripwire. Integrity-verified the new hash sha512-ePWsvanv…WQlOw== as a byte-exact match to the official npm registry entry for js-yaml@4.2.0 (published 2026-05-31, past the 7-day cooldown) → not a poisoned tarball → rebase-merged (all 4 required checks green).
  • Filed #2015: the [lockfile-only] ack marker is structurally invisible to PR CI. check_lockfile_integrity.py reads git log -1 HEAD, but on a pull_request event the default actions/checkout checks out the synthetic merge commit (refs/pull/N/merge, message "Merge X into Y") — the marker lives on parent-2 (the PR head), so it never suppresses the failure. A human-reviewed transitive lockfile bump can never turn detect green via the marker. detect is non-required (so we merge after manual review, as s160 did for #2005), but it is a recurring papercut. Proposed fix in the issue: scan the PR commit range for the marker (or pass --head ${{ pull_request.head.sha }}), plus a unit test.

Lessons / reusables

  • Brief files in logs/remediation/briefs/ are gitignored → they do NOT reach author worktrees. Batch A authors reported the per-module brief files were "not present" and fell back to web search + the inline prompt. It worked out (all facts verified correct), but it is fragile. Fix applied mid-session for Batch B: inline the LOCKED facts directly into the dispatch prompt (not just a file path). The one critical fact I had inlined in Batch A ("Crossplane is now CNCF Graduated, not Incubating") is exactly what saved 7.2. For worktree dispatches, either commit the brief to main first or inline the facts.
  • codex pastes inlined brief blocks verbatim into content. Given the locked facts inline, codex (kubebuilder) copied the entire block — including authoring meta-instructions ("Do NOT label…", 'Say "verify…"', "do not invent fields", "state this precisely") — into the learner-facing snapshot. cursor and deepseek rephrased into prose; codex did not. When inlining facts for codex, phrase them as the desired learner sentence, not as an instruction, and grep the output for instruction-leak phrasing (do not | say " | state this precisely) at review.
  • The revision_pending:false brief rule held — all 5 flipped to done on finalize_module.sh with no manual frontmatter flip (the s130/s160 bug stays fixed).
  • Process-liveness check gotcha: ps is aliased to procs here (rejects aux/-A). Use /bin/ps -axo … to see real dispatch processes — I briefly mis-diagnosed two live dispatches as dead because the alias filtered them out. The s160 rule holds: check git -C <wt> log/status (the worktree was being modified) before declaring a dispatch dead.
