THE KEY MECHANISM (session 73 left this unspecified — now traced & proven)

Session-73's plan said "APPROVE → mark reviewed (done)" but never said how. The board's _quality_board_classify returns done only when score≥4 AND stage∈{COMMITTED,SKIPPED} (or no state file) AND latest_verdict≠reject. The 279 shipped_unreviewed sit at stage=UNAUDITED with a state file → a review verdict alone does nothing.

Do NOT just run the pipeline to fix this. stages.py route sends score-5.0/density-PASS/structurally-complete content to CITATION_CLEANUP_ONLY → COMMITTED, skipping the teaching review (code comment: judge "deferred to Phase 2a", unimplemented). That would mark the back-catalog done WITHOUT the cross-family review the 80%-NEEDS_CHANGES data demands — metric-gaming.

The honest bridge (no new code), per module:

1. Dispatch real cross-family review (dispatch_smart.py review --agent codex --worktree <wt> --mode danger,
   or cursor/gemini). Read FULL verdict from logs/dispatch_responses/<task-id>.txt (wrapper tails only).
2. NEEDS_CHANGES → fix on worktree branch (cursor), PR (chore(content): + ## Learner check blockquote
   >=30 chars verbatim from a touched file IN THE PR BODY), green build, merge. Re-review only if the
   fix is non-trivial — self-verify mechanical 1-liners to save a dispatch.
3. Write .pipeline/reviews/<key-with-__>.md whose LAST heading matches
   ^## <ISO-ts> — `REVIEW` — `APPROVE`   (key = path minus .md, / → __)
4. python3 -m scripts.quality.pipeline reset-stage <slug> COMMITTED   (slug = path / → -, minus .md; run -m!)
→ board flips to done.

Saved to memory feedback_review_to_done_mechanism. Reusable finalize-script pattern (records + reset-stage): see /tmp/finalize-zt-done*.sh in-session (reproduce per batch). Board state (.pipeline/reviews + quality-pipeline) is gitignored = local-only — the local /quality dashboard reads it; content fixes are durable on main via the PRs.
