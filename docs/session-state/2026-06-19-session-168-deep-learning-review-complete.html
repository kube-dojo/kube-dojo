Findings / lessons

  • Triage was wrong; the verifier is the truth. The s167b note said all 16 were "dense T0=review." Authoritative verify_module.py showed 1.8 and 1.9 were genuine T3 (body floor + outcome alignment + structure), and 1.7's earlier "fail" was a flaky sources_all_reachable network blip (passes cleanly on re-run — the verifier fetches every source URL). Run the verifier per-module, don't trust a prior batch summary.
  • density.py badly under-counts prose on these files — it reported 942/2127/6503 prose-w for 1.8/1.9/1.10 vs the verifier's 4966/4886/5601 body_words (a 5× gap, not the known ~12%). Trust verify_module.body_words for the expand/review split; density.py is unreliable on at least these three. (Extends the standing s162 reconcile-counters finding.)
  • Ground-checking every P1 paid off both ways. Rejected one agy P1 as a hallucination (it quoted model(x.view(-1, 28*28)) with x=ones(4,8) — that code does not exist; the real line is an illustrative logits = model(x) fragment). Downgraded one codex P1 (perm-equivariance is the standard, correct PE motivation). Confirmed 1.7's two P1s as real.
  • Heredoc footgun: an unquoted <<PY heredoc ran bash command-substitution on backtick code-spans (`Data`, `GCNConv`…) inside the 1.9 checkbox — silently deleting them ("command not found"). The verifier still passed (plain tokens survived), masking the corruption. Caught on diff review and fixed. Always quote heredocs (<<'PY') when content contains backticks.
  • Web-verified DeepSeek-V2's "93.3% KV-cache reduction" (1.10) — confirmed exact in the arXiv 2405.04434 abstract.
