5. The calibration-leak trace: how the stray rbac.md got into primary tree

Session 36 carryover #7 flagged src/content/docs/k8s/cka/rbac.md as an "investigate stray" — 52 KB hand-drafted K8s 1.35 RBAC content of unknown origin. It sat untouched through sessions 37 + 38. Session 39 git-hygiene discarded it ("not the current pedagogical direction") and filed #1384 to capture the TTT framework idea.

An hour later, while investigating Flash-3.5-High's content-writing-long collapse, the source became clear. The fixture prompt at scripts/calibration/prompts/v1/content-writing-long/kubedojo-rbac-module.md ends with "Return the full module Markdown" but doesn't explicitly forbid writes to disk. Two models (claude-sonnet-4-6 and gpt-5.4-mini) interpreted "make the module exist" as a write-to-disk instruction:

gpt-5.4-mini (688-byte response): "The full module is in [module-1.6-rbac.md](/Users/.../src/content/docs/k8s/cka/part1-cluster-architecture/module-1.6-rbac.md). Verifier result: T0 with 5239 body words..."

claude-sonnet-4-6 (822-byte response): "The module is self-contained and drops directly into src/content/docs/k8s/cka/part1-cluster-architecture/module-1.6-rbac.md..."

Both models wrote to the real CKA module path during calibration. The scorer correctly penalized them (link-summary fails verifier gates), but the side effect was unsandboxed writes to primary tree. The orphan rbac.md + the TTT-pedagogy modifications to module-1.6-rbac.md that I reverted earlier in the session were both calibration responses leaking through.

Filed as #1390 with 3 fix options: prompt-side ("DO NOT write to disk"), dispatch-side (tmp-worktree sandbox), scorer-side (respected_inline_return gate).
