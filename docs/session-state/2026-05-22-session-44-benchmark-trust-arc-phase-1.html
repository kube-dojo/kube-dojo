Composite scoring system

Replaced the matrix's 0%/50%/100% ratio (only 3 possible values) with a continuous 0–10 composite + letter grade. Math (locked in scripts/calibration/constants.py):

# Mechanical lanes (no LLM judge by design):
composite = gate_pass_ratio × 10

# Prose lanes (has 2 LLM judges):
gate_component  = gate_pass_ratio × 10           # 0–10
judge_component = mean(parsed_judge_scores)      # already 0–10
composite = 0.4 × gate_component + 0.6 × judge_component

# Prose lane where both judges crashed:
composite = 0.4 × gate_component   # penalized for missing judgment

Letter bands: A 8.5–10 B 7.0–8.5 C 5.5–7.0 D 4.0–5.5 F 0.0–4.0

Operational notes

Hook discipline matters — but is overly strict for chore-class CI fixes

The chaos-monkey unblocker PR (#1444) hit 3 different hooks in sequence: missing learner-check, missing regression-test line, and missing verbatim quote. The verbatim-quote check is correct — it's the difference between "I read the file" and "I paraphrased from memory" — but it does mean a 1-character-position fix takes 4 PR-body iterations. The chore(...) title prefix bypasses the bugfix-regression-test hook, which is the correct escape hatch when the regression-test discipline is overkill for the change.

Composite scoring is render-only, so weights can be retuned without re-firing

Critical design choice from the dispatch brief: compute composite at render time from existing ledger rows. COMPOSITE_GATE_WEIGHT and COMPOSITE_JUDGE_WEIGHT live in scripts/calibration/constants.py as config; tuning them is a one-line PR + re-render, not a new dispatch. Same goes for letter-grade band thresholds. If after a week of looking at the new matrix the user wants 0.5/0.5 instead of 0.4/0.6, that's a 30-second change.

Re-scoring 28 cells against the new scorer was instant

Both content-review and fact-check are mechanical lanes — no LLM judge to re-fire. scripts/calibration/score_cell.py --no-render on each of the 28 cells took <1s each. The dispatch data was reused from 2026-05-21; only the score rows were rewritten. This is the right shape for the future: dispatch and scoring are decoupled, so a scorer fix is always cheap to verify against historical data.
