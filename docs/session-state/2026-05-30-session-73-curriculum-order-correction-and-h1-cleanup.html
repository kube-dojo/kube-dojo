THE PROGRESSION — review-first, in curriculum order

Process tracks in curriculum order: prerequisites → linux → ai → k8s → cloud → ai-ml-engineering → on-premises → platform (ai-history excluded). Within a track, ascending module number. The dashboard moves when modules become done (reviewed), so review is the spine; authoring is what un-sticks the modules that can't pass review yet.

Phase 0 — deterministic / gate fixes (cheap, no fabrication risk)

  • Leaked-H1: DONE repo-wide.
  • kubectl-alias gate: DONE. Follow-up: the 43 alias-less k modules (real copy-paste bug the retune exposed) — add alias k=kubectl to follow the convention. Small per-module edit; codex, batched.
  • Sweep other deterministic gate fails as found (leaked placeholders, etc.) with scripts, not agents.

Phase 1 — REVIEW the unreviewed (396: 279 shipped_unreviewed + 117 needs_review)

Prioritise modules that are already verifier-T0 + rubric ≥ 4.5 — they'll mostly pass review → done fast. Start with prerequisites (38 to review; mostly score 5.0) so that section finally turns green, then linux, ai, k8s, …

  • Each module: cross-family review (rubric + verifier + fabrication/factual check) per docs/review-protocol.md + Decision Card C.
  • Verdict APPROVE → mark reviewed (done). NEEDS_CHANGES → drop into Phase 2.
  • Caveat (feedback_back_catalog_full_review_required): a 2026-05 sample of shipped_unreviewed was ~80% NEEDS_CHANGES — expect real bounces, especially low-score tracks. High-score prereq/ai-ml will pass cleanly; platform's needs_rewrite:135 won't.

Phase 2 — REWRITE / AUTHOR the failures (181 needs_rewrite + Phase-1 bounces)

These are the genuinely-thin (body_words median 2012w), war-story, and structural failures. Fabrication-prone — every output cross-family reviewed before merge.

  • Thin / body_words: full authoring to ~5000+ words with real sources (the module-writer brief). Curriculum order.
  • War-stories (155 files): per user — real source or remove; each incident told once, referenced elsewhere (dovetails with the CI incident-dedup gate). Most fabrication-inducing task → fetch primary sources via browser BEFORE the author brief; mandatory review.
  • Density-only (1 module): cursor de-frag.
  • Then re-review (Phase 1) → done.
