Key finding — pf-mlops is a REFLOW wave, not a rewrite wave

The s172b handoff framed the remaining pf-mlops 9 as "systematic short-paragraph density failures… budget as its own multi-session wave" implying heavy rewrites. Ground-truthing corrected this: all 9 fail the density cluster because the teaching prose is written one sentence per paragraph (every sentence on its own line, blank line between → median words-per-paragraph ~7–9 vs the 28 floor). Verified against extract_body_paragraphs in verify_module.py — it excludes code/tables/lists/<details>, so this is genuine prose fragmentation, not a metric artifact. The content is largely decent; the fix is a faithful reflow (join sentences into 4–6 sentence paragraphs), which is far cheaper than a rewrite. One author wrote the whole sub-track this way (consistent med_wpp).

  2. opus-inline cross-family review (cursor=Kimi base → opus is cross-family; pure-prose change = no code-exec review needed). Ground-check: verify_module.py T0 + (a) headings-identical diff (no section dropped), (b) body_words preserved/up (a gutting drops it — both went UP), (c) opener labeled, (d) named-entity fab-grep on added lines, (e) sources reachable AND academic titles confirmed.
  3. PR → required CI (Astro build gate) → rebase-merge → finalize_module.sh (guard APPROVE record → reset-stage COMMITTED → record-build) → commit records direct-main (git add -f).
