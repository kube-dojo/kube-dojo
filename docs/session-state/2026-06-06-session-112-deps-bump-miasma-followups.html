Load-bearing lesson #1 — the local build verify earned its keep (again)

The Dependabot bump #1800 was all-green in PR CI and would have merged straight into a broken main. Starlight 0.39 is a BREAKING change for autogenerated sidebar groups; the unmigrated astro.config.mjs fails npm run build with Invalid config passed to starlight integration. PR CI has no full Astro build (it runs site-health + CodeQL + incident-dedup + the supply-chain detect job, not astro build) — exactly the feedback_pr_ci_has_no_full_astro_build blind spot. Session 111 flagged "needs a local build verify before merge"; doing it caught the break.

The 0.39 migration (two breaking changes, from the installed CHANGELOG):

  • Autogenerated sidebar groups must now be wrapped in an items: [...] array: { label, autogenerate, collapsed } → { label, collapsed, items: [{ autogenerate }] }.
  • collapsed no longer cascades from a parent group to its autogenerated subgroups → add autogenerate.collapsed: true to preserve current behavior.

Applied as a deterministic regex transform across all 104 sidebar sites (103 single-line + 1 multi-line Foundations block) — not hand-edited, so no drift. Rebuilt under astro 6.4.2 + starlight 0.39.2 → green, 2163 pages, 0 errors. codex did an AST-level review (104/104, no double-wraps, collapsed preserved) → APPROVE. After merge, primary's node_modules was resynced (npm ci) to the new lockfile so future builds in primary are correct. (npm audit: 2 pre-existing moderate dev-only transitive vulns — brace-expansion, ws — not introduced by this bump.)

Load-bearing lesson #2 — a lockfile-swap detector must fingerprint the FULL installer-affecting entry

The new scripts/security/check_lockfile_integrity.py (P2 DETECT, #1812) surfaces any package-lock.json dependency mutation not accompanied by a package.json change — the "silent lockfile swap" that npm ci installs without complaint. The first cut fingerprinted only {version, resolved, integrity}.

codex R1 (adversarial, gpt-5.5) returned NEEDS_CHANGES with two reproduced bypasses (it built disposable npm projects to prove them):

  • bin mutation — repoints a package's .bin/* symlinks to a different script in the same package; tuple delta was [].
  • dependencies-map edit — drops a dependency edge so npm ci installs a different tree; tuple delta was [].

Neither is caught by the existing check_install_scripts.py (it checks link / hasInstallScript / non-registry / alias) nor by npm audit signatures (the tarball + integrity stay valid). Plus a fail-open path: git diff --quiet returncode >1 (error) was collapsed to "changed", which could suppress a real finding via the package.json-changed PASS branch.

R2 fix (cursor): fingerprint the full packages[path] entry minus a tiny deny-list of pure-metadata noise (funding, license, deprecated) — closes the whole class of field-level bypasses, not just the two demonstrated; git diff handling made fail-closed (0→clean, 1→changed, error→exit 2). Orchestrator ground-check re-ran both demonstrated bypasses → now exit 1 (were 0); PASS/override/error paths correct; lockfile byte-identical; ruff + zizmor clean; CI detect job green (the new step runs in real CI). Converged after R2 — the fix is structural (compare everything installer-affecting), so chasing another round would be the infinite-R4 trap the #1813 review warned about.

Note codex also resolved a merge-base FP concern the orchestrator raised: GitHub's pull_request event checks out the merge commit (refs/pull/N/merge), so merge-base == base tip and the structured compare is consistent in real CI — the FP only exists for local non-merge-head runs, and is fail-safe.
