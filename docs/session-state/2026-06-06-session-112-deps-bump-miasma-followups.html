Load-bearing lesson #2 — a lockfile-swap detector must fingerprint the FULL installer-affecting entry

The new scripts/security/check_lockfile_integrity.py (P2 DETECT, #1812) surfaces any package-lock.json dependency mutation not accompanied by a package.json change — the "silent lockfile swap" that npm ci installs without complaint. The first cut fingerprinted only {version, resolved, integrity}.

codex R1 (adversarial, gpt-5.5) returned NEEDS_CHANGES with two reproduced bypasses (it built disposable npm projects to prove them):

  • bin mutation — repoints a package's .bin/* symlinks to a different script in the same package; tuple delta was [].
  • dependencies-map edit — drops a dependency edge so npm ci installs a different tree; tuple delta was [].

Neither is caught by the existing check_install_scripts.py (it checks link / hasInstallScript / non-registry / alias) nor by npm audit signatures (the tarball + integrity stay valid). Plus a fail-open path: git diff --quiet returncode >1 (error) was collapsed to "changed", which could suppress a real finding via the package.json-changed PASS branch.

R2 fix (cursor): fingerprint the full packages[path] entry minus a tiny deny-list of pure-metadata noise (funding, license, deprecated) — closes the whole class of field-level bypasses, not just the two demonstrated; git diff handling made fail-closed (0→clean, 1→changed, error→exit 2). Orchestrator ground-check re-ran both demonstrated bypasses → now exit 1 (were 0); PASS/override/error paths correct; lockfile byte-identical; ruff + zizmor clean; CI detect job green (the new step runs in real CI). Converged after R2 — the fix is structural (compare everything installer-affecting), so chasing another round would be the infinite-R4 trap the #1813 review warned about.

Note codex also resolved a merge-base FP concern the orchestrator raised: GitHub's pull_request event checks out the merge commit (refs/pull/N/merge), so merge-base == base tip and the structured compare is consistent in real CI — the FP only exists for local non-merge-head runs, and is fail-safe.

Load-bearing lesson #3 — the agent-config injection tripwire (#1820) + a static scanner's bypass economy

The Miasma AI-agent-config-injection variant plants auto-exec payloads in AI IDE config files (.claude/, .cursor/, AGENTS.md, CLAUDE.md, MCP configs, …) that run when the repo is opened in an AI IDE. New control: scripts/security/check_agent_configs.py (pre-commit + the detect CI job) — a whole-file scan for high-signal auto-exec compositions only (pipe-to-shell, base64-to-shell, eval-of-cmdsubst/decoded-JS, process-substitution, interpreter--c+downloader, child_process exec, PowerShell IEX, python-remote-exec) — NOT bare keywords, because this repo's configs are full of legit shell (npm run build, localhost curl) and "eval" inside "evaluate". Verified 0 findings on the current tree (41 files).

codex R1 = NEEDS_CHANGES, again with reproduced bypasses (temp repos): (1) fail-open — a non-UTF-8 in-scope file (\xff + curl|sh) was silently skipped despite the "fail-closed" docstring; (2) missed download-and-execute forms — bash <(curl…), python -c "$(curl…)", sh -c "$(curl…)", source /dev/stdin, curl -o /tmp/x; bash /tmp/x; (3) scope gaps — MCP configs (.mcp.json/.vscode/mcp.json — which literally define commands that run!), .aider.conf.yaml, .roo/.clinerules/.windsurf dirs, .github/instructions/, plus a needless scripts/ blind spot; (4) FP — \bIEX\b matched Elixir iex. R2 fix: decode errors="replace"+still-scan (fail-closed); +5 downloader-anchored patterns + backslash-continuation joining; scope expanded (MCP + the above, scripts/ un-excluded); bare IEX made case-sensitive. Orchestrator ground-checked all 9 R1-proven payloads → exit 1; non-UTF-8 → exit 1; evil MCP config → exit 1; Elixir iex → exit 0 (FP gone); current tree → exit 0.

The meta-lesson (reinforced twice this session): a static pattern scanner can be gamed at the margins forever. The convergence rule from #1813 holds — fix every demonstrated bypass + the structural class (here: fail-open, and downloader-anchored compositions), then converge rather than chase an infinite review loop. The suppression markers ([lockfile-only], agent-config-allow) are honestly documented as acknowledgement markers, not authorization controls — their value is forcing a human to review a flagged line.
