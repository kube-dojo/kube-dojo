Failure classes consistent across composer-2.5 author output:

  1. Bash runnability inside fenced blocks — angle-bracket URLs (``) break copy-paste; CLI flag/column-name typos.
  2. Version-pin inconsistency — prose claims K8s 1.35 but exercise pins v1.30 or installs incompatible clusterctl.
  3. Factual subject-matter slips — Rancher Fleet called "push" (it's pull); Argo CD ApplicationSet generator behavior conflated; BareMetalHost lifecycle wording wrong vs Metal3 docs; OCM PlacementBinding semantics wrong.
  4. Operationally dangerous snippets — #1477 had "cordon a MachineDeployment" via spec.replicas: 0, which scales-down/deletes Machines rather than cordoning nodes.
  5. Citation reachability — broken URLs in Sources or Exercise 2 (404s).

Verifier passes on all 4 modules (passed=true, tier=T0, body_words=5000 on every original commit). Verifier ≠ T0 quality. The verifier catches mechanical gates (body_words, sources_min_10, sections, MD034) — not subject-matter accuracy, not bash runnability inside fenced blocks, not version-pin consistency.

This is the same profile as deepseek-v4-pro authoring (feedback_deepseek_v4_pro_viable_for_t0_content): viable T0 author, needs vigilant code-domain reviewer. The "viable T0 author with code-domain runnability gap" appears to be the modal capability across our author agents, not unique to one.

Operational lessons (new)

  1. Always anchor cd before any dispatch chain. Orchestrator forgot once tonight and ended up creating nested worktrees inside the cursor-private-cloud worktree because Bash cwd had persisted from a prior cd. Cost ~10 min of damage-control. Pattern: always start dispatch sequences with cd /Users/krisztiankoos/projects/kubedojo && pwd in the same Bash call as the dispatch.
  2. codex review = --mode danger --worktree mandatory. Re-confirmed feedback_codex_review_danger_mode after forgetting and seeing 3 dispatches die instantly with "no override" arg-validation errors. dispatch_smart.py refuses if you try to skip either.
  3. Cursor adapter in ab discuss breaks on monitor_state_snapshot. Bug for follow-up: strip or quote monitor state before passing to cursor-agent CLI.
  4. Anti-rubber-stamp briefs work. Codex with explicit "list 4 concrete things you verified" requirement produced consistently rigorous reviews. Deepseek did not follow the requirement even with similar brief — that's an agent quality difference, not a prompt-writing difference.
  5. Detached HEAD trap on primary. A reviewer dispatch did a git fetch which left primary at FETCH_HEAD; recovered with git checkout main. Look for this pattern at session start every time.
