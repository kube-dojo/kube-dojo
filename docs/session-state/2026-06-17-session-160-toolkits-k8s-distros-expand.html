Lessons / reusables

  • Brief bug → fixed in the reusable brief: the expand brief said "leave frontmatter intact," which made authors keep revision_pending: true. The board treats revision_pending: true as needs_rewrite regardless of stage/verdict/score, so all 3 stayed off done after finalize until I flipped the field. Every expand brief must say "set revision_pending: false" (this recurred — same note in s130's #1896). I also asserted "revision_pending:false" in the APPROVE records before verifying it — corrected, but a reminder to check, not assume.
  • Board done = score≥4 + stage COMMITTED + verdict approve + revision_pending:false. After a content merge, score auto-rescores (1.5→5.0) but you still must flip revision_pending; the board reads it from the live frontmatter, not git.
  • Don't Read files inside .worktrees/ — it re-injects the whole CLAUDE.md + rules bundle (~15K tokens) per read. Use Bash (sed/grep/python) for worktree files; Read only primary-dir files.
  • Worktree build works via ln -s ../../node_modules (symlink primary's node_modules into the integration worktree) → full npm run build green (2169 pages, 47s) without branching in primary.
  • codex OK:False on a danger-mode dispatch is the stale-origin push check (work committed cleanly; push the branch yourself), not a failure. deepseek had no gutter corruption this wave (proactively fixed an XXX leak token too).
  • Reusable briefs: logs/remediation/briefs/k8s-distros-expand.md (shared rules), logs/remediation/briefs/k8s-distros/ (per-module specs + REVIEW-TRUTH.md ground-truth + _finalize.sh).
