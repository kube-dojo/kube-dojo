**Почніть звідси, якщо ви шукаєте найкоротший шлях від основ для початківців до Kubernetes та платформної інженерії.**

Цей хаб є головним входом до KubeDojo. Він охоплює термінал, контейнери, основи Kubernetes, декларативне мислення, Git та сучасні практики доставлення програмного забезпечення.

## Для кого це

- абсолютних новачків, яким потрібна справжня точка відліку
- студентів, які шукають найкоротший шлях до хмарно-нативних систем
- людей, яким потрібні міцні основи перед вибором напрямків Linux, Kubernetes, хмарних технологій, платформної інженерії, ШІ-грамотності або глибинного вивчення AI/ML

## Не пропускайте це, якщо

- ви досі не впевнено користуєтеся терміналом, файловою системою, SSH або не знаєте, як встановлювати програмне забезпечення
- термінологія Kubernetes все ще здається абстрактною
- у вас є спокуса одразу перейти до просунутих напрямків, бо вони виглядають цікавішими

Більшість непорозумінь на пізніших етапах навчальної програми виникає саме через те, що цей базовий рівень було пропущено занадто рано.

## Пропонований маршрут

```text
Від нуля до термінала
   |
   +--> Напрямок Linux (якщо ви хочете глибших знань про системи)
   |
Основи Cloud Native 101
   |
Основи Kubernetes
   |
Філософія та дизайн
   |
Глибоке занурення в Git
   |
Сучасний DevOps
```

Використовуйте `Глибоке занурення в Git` після того, як ви будете впевнено користуватися базовим Git з розділу `Від нуля до термінала`. Цей курс не є обов'язковим перед `Основи Cloud Native 101` або `Основи Kubernetes`, але його слід розглядати як практичну передумову перед серйозною роботою з IaC, GitOps, CI/CD та командними робочими процесами.

Практичне правило є простим:

```text
0.6 Основи Git
   |
Глибоке занурення в Git
   |
Сучасний DevOps / IaC / GitOps / CI-CD
```

## Git не є опціональним для сучасної інфраструктурної роботи

Послідовність має значення:
- `0.6 Основи Git` у розділі `Від нуля до термінала` дає вам мінімально життєздатний робочий процес
- `Глибоке занурення в Git` перетворює Git на операційний інструмент, а не просто механізм для резервного копіювання
- лише після цього `Сучасний DevOps`, `IaC` та `GitOps` стануть набагато простішими для правильного використання

Якщо студент пропускає вивчення Git, він все ще зможе читати пізніші модулі, але йому бракуватиме однієї з ключових навичок, що лежить в основі сучасної інфраструктурної практики.

## Поширені наступні маршрути

- `Передумови -> Linux`, якщо ви прагнете глибшого розуміння систем перед роботою, яка вимагає інтенсивних операційних завдань
- `Передумови -> Сертифікації Kubernetes`, якщо ви орієнтуєтеся на зовнішні цілі та хочете відчути тиск практичної роботи
- `Передумови -> Хмарні технології`, якщо ваша головна мета — вільне володіння інструментами гіперскейлерів після засвоєння основ кластерів
- `Передумови -> ШІ`, якщо ви шукаєте справжній шлях для початківців до ШІ-грамотності та дисциплінованого використання ШІ
- `Передумови -> AI/ML Інженерія`, якщо ви вже знаєте, що хочете створювати ШІ-системи, запускати локальні моделі або рухатися в напрямку MLOps
- `Передумови -> Сучасний DevOps` зазвичай має означати `Від нуля до термінала -> Глибоке занурення в Git -> Сучасний DevOps`, а не прямий стрибок, що оминає впевнене володіння Git

`Платформна інженерія` зазвичай не є безпосередньою наступною зупинкою для новачків. Більшість студентів повинні спершу дійти до неї через Kubernetes, Linux або хмарні технології.
